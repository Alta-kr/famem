# Daynote

**적기만 하세요. 정리는 Daynote가.** — 아무 형식 없이 던진 글을 AI가 할 일 / 일정 / 메모 / 아이디어 / 링크로 나눠 제자리에 넣는 데스크톱 메모앱.
설계: `../DAYNOTE_UX_V2.md` (v2 기준) · 이전: `../DAYNOTE_CLAUDE_DESIGN_BRIEF.md`, `../DAYNOTE_CLAUDE_WORK_PROMPTS.md`

## 주요 기능

- **슬래시 명령어** — 입력창 맨 앞에 `/`를 치면 목록이 떠요. `/할일 내일까지 보고서`, `/일정`, `/메모`, `/아이디어`, `/링크`는 AI를 기다리지 않고 바로 그 종류로 저장하고, 뒤에 AI가 이어서 다듬어요. `/상태 퇴근`은 현재 상태를 바꾸고, `/도움말`은 명령어 안내를 보여 줘요. 영어(`/todo`)와 한 글자 줄임(`/t`)도 되고, 한글 자판 상태로 `/ㅎ`을 쳐도 `/할일`로 알아봐요. 맨 앞에 `//`를 두면 명령어가 아니라 그대로 `/`로 시작하는 글이에요.
- **할 일 추천 패널** — 오늘 화면에서 비어 있는 때 ‘할 일 추천’ 버튼이 보여요. 15분·30분·1시간·직접(`1:30`) 중 쓸 수 있는 시간을 고르면 그 안에 끝낼 수 있는 일을 골라 주고, ‘다른 후보’와 ‘지금 시작’이 있어요.
- **근무 시간** — 설정 → 근무 시간에서 요일·시작·끝을 정해요. 추천과 ‘다른 시간 찾기’가 이 시간을 기준으로 하고, 근무 시간 밖에는 남은 시간을 짐작하지 않고 물어봐요.
- **현재 상태** — ‘퇴근’, ‘회의 중’, ‘이동 중’ 같은 말을 입력창에 적거나 `/상태`로 알려 주면 그에 맞게 추천과 화면이 바뀌어요. 상태 칩에서 바꾸거나 이전 상태로 되돌릴 수 있고, 설정 → 현재 상태에서 규칙을 정해요.
- **Daynote가 배운 것** — 사용자가 고친 분류·날짜 같은 선택을 규칙으로 기억해 다음에 먼저 적용해요. 설정 → Daynote가 배운 것에서 보고, 하나씩 잊게 할 수 있어요.
- **캘린더** — 월간 보기 · 끌어서 자동 배치 · 날짜 위에서 1초 기다리면 그날 열기 · 배치 힌트(AI가 함께 짐작)
- **Google 캘린더 연결** — 일정을 가져오고, Daynote 일정을 ‘Daynote’ 캘린더로 올려요 (데스크톱 앱, 아래 설정 안내).

## 실행

```
npm.cmd install        # Electron 32 설치 (처음 한 번)
npm.cmd start          # 앱 실행 (PowerShell 에서는 npm 대신 npm.cmd)
npm.cmd test           # 업무 규칙 테스트 (Node 내장 테스트)
npm.cmd run smoke      # 창을 띄우지 않고 모든 화면이 그려지는지 확인 (가짜 AI, smoke 전용 프로필)
npm.cmd run shots      # 창을 띄우지 않고 화면별 스크린샷 → screenshots/ (가짜 AI)
npm.cmd run serve      # 브라우저 검증용 정적 서버 → http://localhost:5178 (?fakeai 로 데모 AI)
```

### AI 키 (Google AI Studio)
- 설정 → AI 연결에 키를 붙여 넣으면 Windows 보안 저장소(DPAPI)로 암호화해 저장한다. 화면에는 끝 4자리만 보인다.
- 개발용으로 앱 폴더의 `.env` (`GEMINI_API_KEY=...`)나 환경변수도 읽는다. 우선순위: 설정에 저장한 키 > 환경변수 > `.env`.
- 켜질 때 키를 AI 모듈 안으로 옮기고 `process.env` 에서 지워 화면 프로세스가 물려받지 않게 한다. 오류 메시지 속 키는 가린다.
- 모델: 던진 글 분류는 `gemini-3.5-flash-lite`(thinking minimal, 실측 2~5초), 작게 나누기·메모 정리는 `gemini-3.8-flash`(low). 한쪽이 일시 오류면 다른 쪽으로 대신한다.

### Google 캘린더 연결 (처음 한 번, 10분쯤)

Daynote는 Google 캘린더의 일정을 가져와 캘린더 화면과 ‘다음 할 일’ 추천에 바쁜 시간으로 쓰고,
Daynote에서 만든 일정·작업 시간을 Google 캘린더의 **‘Daynote’ 캘린더**에 올립니다.
아직 Google 앱 확인을 받기 전이라, 연결하려면 본인 Google Cloud 프로젝트에서 OAuth 클라이언트를 한 번 만들어야 합니다.

1. **프로젝트 만들기** — https://console.cloud.google.com 에 로그인 → 위쪽 프로젝트 선택 → **새 프로젝트** → 이름 `Daynote` → 만들기.
2. **Calendar API 켜기** — 왼쪽 메뉴 **API 및 서비스 → 라이브러리** → `Google Calendar API` 검색 → **사용**.
3. **동의 화면(Google 인증 플랫폼)** — 왼쪽 메뉴 **Google 인증 플랫폼**(예전 이름: OAuth 동의 화면) → **시작하기**
   - 앱 정보: 앱 이름 `Daynote`, 사용자 지원 이메일 = 내 주소
   - **대상: 외부(External)** → 연락처 이메일 → 정책 동의 → 만들기
   - 게시 상태는 **테스트(Testing)** 그대로 둡니다.
4. **테스트 사용자 추가** — **대상(Audience)** → **테스트 사용자 → 사용자 추가** → Daynote에 연결할 Gmail 주소 입력 → 저장.
   (여기에 없는 계정으로 로그인하면 “액세스 차단됨/access_denied”가 뜹니다.)
5. **범위 추가(권장)** — **데이터 액세스** → **범위 추가 또는 삭제** → 아래 세 개를 찾아 체크 → 업데이트 → 저장
   - `.../auth/calendar.calendarlist.readonly` (캘린더 목록 보기)
   - `.../auth/calendar.events.readonly` (일정 보기)
   - `.../auth/calendar.app.created` (Daynote가 만든 캘린더만 만들고 고치기)
6. **OAuth 클라이언트 만들기** — **클라이언트 → 클라이언트 만들기**
   - 애플리케이션 유형: **데스크톱 앱** (웹 애플리케이션이 아닙니다)
   - 이름: `Daynote 데스크톱` → 만들기
   - 뜨는 창에서 **클라이언트 ID**와 **클라이언트 보안 비밀번호**를 복사하거나 **JSON 다운로드**를 누릅니다.
     보안 비밀번호는 **만들 때 한 번만** 보입니다. 놓쳤다면 그 클라이언트에서 새 보안 비밀번호를 추가하세요.
7. **Daynote에 붙여 넣기** — Daynote → **설정 → 캘린더**(‘준비 필요’) → 클라이언트 ID·보안 비밀번호를 붙여 넣거나
   **JSON 내용으로 붙여 넣기**에 내려받은 파일 내용을 통째로 붙여 넣고 **저장** → **Google 계정으로 연결**.
8. 브라우저가 열리면 4번에 넣은 계정을 고릅니다. “Google에서 확인하지 않은 앱” 화면이 나오면 본인이 만든 앱이므로
   **고급 → Daynote(으)로 이동**을 누르고, 권한 화면에서 **모든 항목에 체크**한 뒤 계속합니다.
   “Daynote에 연결했어요” 탭이 보이면 닫고 Daynote로 돌아가면 됩니다.

알아 둘 점
- 클라이언트 보안 비밀번호는 설치형 앱 특성상 완전한 비밀이 아니지만, Daynote는 이 컴퓨터에 암호화해 두고 화면·백업·로그에 내보내지 않습니다. GitHub 등에 올리지 마세요.
- **테스트 모드 앱은 Google 정책상 7일마다 다시 로그인해야 합니다.** 설정에 ‘다시 로그인이 필요해요’가 보이면 **다시 연결**을 누르세요.
  (개인용으로 **앱 게시 → 프로덕션**으로 바꾸면 7일 만료는 없어지지만, ‘확인되지 않은 앱’ 경고는 계속 보입니다.)
- 로그인 정보(refresh token)는 Windows 보안 저장소(DPAPI)로 암호화해 `%APPDATA%\daynote\google-token.bin`에 둡니다. 데이터 파일·백업에는 들어가지 않습니다.
- 연결 해제는 설정 → 캘린더 → **연결 해제**. 이 컴퓨터의 로그인 정보를 지우고 Google에도 권한 해제를 요청합니다. Google 쪽은 https://myaccount.google.com/connections 에서도 확인·해제할 수 있습니다.
- Google 캘린더의 ‘Daynote’ 캘린더를 지우면 Daynote가 올린 일정도 함께 지워집니다. Daynote의 일정은 그대로입니다.

개발용 설정 (설정 화면 대신)
```
# 앱 폴더 .env (git 에 올리지 않음) 또는 환경변수 — 설정에 저장한 값이 있으면 그쪽이 우선
GOOGLE_CLIENT_ID=1234567890-abcdefg.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-...
```
(`DAYNOTE_GOOGLE_CLIENT_ID` / `DAYNOTE_GOOGLE_CLIENT_SECRET` 도 읽고, 있으면 그쪽이 먼저입니다. `GOOGLE_API_KEY` 는 Gemini 키 이름이라 쓰지 않습니다.)

### 데스크톱 동작
- **어디서나 `Ctrl+Shift+Space`** → 화면 위쪽에 빠른 메모 창. 적고 Enter 면 홈 입력과 똑같이 처리된다.
- 창을 닫으면 트레이로 숨는다(설정에서 끌 수 있음). 완전히 끄려면 트레이 아이콘 → 끝내기. 두 번 실행하면 떠 있는 창을 보여 준다.
- `Ctrl+K` 검색·명령, `Alt+1~6` 화면 이동, `/` 입력·검색칸으로.

- 데이터: `%APPDATA%\daynote\daynote-data.json` (직전 정상본 `.bak` 함께 보관). 설정 화면에서 위치 열기·백업 내보내기 가능.
- `electron . --profile=이름` 으로 켜면 다른 폴더에 저장 — 실제 데이터와 분리해 시험할 때.
- 처음 켜면 비어 있다. 오늘 화면의 ‘샘플 데이터로 둘러보기’로 시연 데이터를 넣고, 위쪽 띠의 ‘샘플 지우기’로 샘플만 지울 수 있다.

## 핵심 규칙

- **같은 할 일은 하나.** 메모·캘린더·프로젝트·추천 모두 `tasks` 의 같은 객체를 id 로 참조한다.
- **마감일 ≠ 작업 시간.** 마감일은 `dueDate/dueTime`, 실제로 일할 시간은 `blocks`(여러 개 가능). 블록을 지워도 할 일은 남는다. 할 일을 지우면 앞으로 잡힌 블록만 지우고 지난 블록은 남긴다.
- **소요 시간 미정은 null.** 0분으로 보지 않는다. AI 추정값은 `estimateSource:'ai'` 로 표시하고, 사용자가 확정할 수 있다.
- **완료 취소.** 방금 한 완료를 되돌리면 히스토리 기록을 지운다. 나중에 다시 열면 과거 기록은 ‘완료 취소됨’으로 남기고 취소 기록을 새로 남긴다.
- **원본 삭제.** 히스토리·보고서·출처는 지워진 원본을 조용히 옛 이름으로 보여주지 않고 ‘원본 삭제됨’으로 표시한다.
- **새 할 일 제안 vs 지금 할 일 추천.** 제안은 메모·메일에서 아직 없는 할 일을 찾고, 수락해야 Task 가 된다(같은 출처·문장은 key 로 한 번만). 추천은 이미 있는 Task 중에서 고르고 아무것도 만들지 않는다.
- **메일은 연결했을 때만 읽는다.** 메일·메모 본문은 처리할 문자열일 뿐이며 앱의 동작을 바꾸지 않는다.

### 지금 할 일 추천 (recommend.js)

- 제외: 완료 · 삭제/보관 · 대기 · 선행 업무 미완료 · 미루기 시각 전.
- 쓸 수 있는 시간 T: 사용자가 고른 값(15분·30분·1시간·직접) → 없으면 앱 캘린더의 다음 일정까지 남은 시간(‘후보’로 표시) → 일정 중이거나 남은 일정이 없으면 모름.
- 적합도: `fits` / `step_fits`(긴 업무의 작은 단계 제안) / `unknown`(미정) / `too_long`(목록에서 빼고 따로 안내).
- 정렬: ① 시간 적합(맞음→미정) ② 마감 긴급도(지남→오늘→내일→7일 내→이후·없음) ③ 이어하기(진행 중·지금 작업 시간) ④ 우선순위 ⑤ 마감 시각 ⑥ 남는 시간이 적은 순 ⑦ 만든 순 → id.
- 기본 1개 + 대안 2개, 이유는 실제 입력으로만(백분율 없음).
- 다시 평가: 패널에서 한 동작(시작·완료·미루기·배치) 직후, 시간 선택 변경, 새로고침 버튼. 다른 곳의 변경은 읽던 추천을 바꾸지 않고 ‘정보가 바뀌었습니다 · 다시 추천’을 띄운다. 미루기 만료와 15분 경과도 같은 알림. ‘지금 시작’은 실행 직전 상태를 다시 확인한다.

## AI 메모 정리 (1단계: 메모 → AI 정리 → 초안 검토 → 선택 저장)

```
$env:GEMINI_API_KEY = "AIza..."         # 기본: Google Gemini 3.8 Flash (무료 등급 있음)
$env:ANTHROPIC_API_KEY = "sk-ant-..."   # 또는 Anthropic Claude Opus 5.5 (유료)
$env:DAYNOTE_AI_PROVIDER = "claude"     # 두 키가 다 있을 때 Claude 로 고정하고 싶으면 (기본은 gemini)
npm start
$env:DAYNOTE_AI_FAKE = "1"              # 키 없이 흐름만 시험: 규칙 기반 데모 모드 (화면에 표시됨)
```

키는 환경변수로만 읽고 앱에 저장하지 않는다. Gemini 키는 https://aistudio.google.com 에서 무료로 만든다. 무료 등급에서는 보낸 내용이 Google 제품 개선에 쓰일 수 있고(설정 화면에 표시), 결제를 연결한 유료 등급에서는 쓰이지 않는다. 요청은 `store: false` 로 보내 Google 쪽에 대화 기록을 남기지 않는다.

브라우저 미리보기는 `http://127.0.0.1:5178/renderer/index.html?fakeai` 로 가짜 AI를 쓸 수 있다.

- **세 층 분리**: 원본(`notes` — AI가 고치지 않음) / AI 결과(`aiRuns`·`proposals`·`noteDigests`) / 확정(`tasks`·`blocks`, `origin:'ai_accepted'`·`proposalId`·출처 연결).
- **책임 분담**: AI(`services/ai.js`, 메인 프로세스)는 해석·분류·요약·초안만. 앱(`src/core/ai/validate.js`·`proposals.js`)이 형식·근거·날짜·시각 검증, 중복, 충돌, 저장, 상태 변경.
- **확정하지 않는 값**: 인용 문장이 원문에 없으면 항목을 버린다. 날짜·시각·길이·장소는 메모 표현으로 앱이 다시 계산해 AI 값과 같을 때만 채우고, 아니면 비워 둔 채 ‘확인 필요’ + 근거 있는 후보 버튼만 보여준다.
- **중복·재실행**: 같은 메모 내용 + 같은 프롬프트 버전이면 API를 다시 부르지 않는다. 초안 key = 종류 + 메모 + 인용 문장 해시(앱이 계산). 수락·제외한 초안은 다시 생기지 않고, 사용자가 고친 초안은 덮어쓰지 않는다(새 AI 결과는 ‘새 버전’으로 옆에). 원문에서 근거가 사라진 초안은 ‘원문이 바뀜(stale)’.
- **저장**: 선택한 항목을 먼저 전부 검사하고, 하나라도 문제가 있으면 아무것도 저장하지 않는다. 저장은 한 번에 되돌릴 수 있다. 일정은 날짜·시각·길이가 있어야 캘린더에 올라가고, 없으면 ‘할 일로 저장’을 고를 수 있다.
- **실패**: 429·5xx·연결 오류는 SDK가 재시도, 그래도 실패하면 ‘다시 시도’. 형식 오류는 한 번 더 요청 후 실패 처리. 앱이 꺼져 끝나지 않은 실행은 다음 실행 때 ‘다시 시도 가능한 실패’가 된다. 어떤 경우에도 메모 저장은 AI와 무관하다.
- **호출**: Gemini 는 `gemini-3.8-flash`, thinking `low`, `response_format` JSON 스키마, `store: false`, 429·5xx·연결 오류는 한 번 재시도. Claude 는 `claude-opus-5-5`, effort `low`, 구조화 출력, 거절 시 서버 측 대체 모델(`fallbacks: "default"`), 고정 지침은 캐시. 두 제공자 모두 같은 프롬프트·스키마·검증기를 쓴다. 메모 본문은 데이터로만 다루고 그 안의 지시는 따르지 않도록 지시한다.
